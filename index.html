수시 상담카드 발표결과판 설치·업데이트 안내

상담카드에 수시 발표 결과 화면이 더해졌습니다. 학생이 실제로 원서를 낸 대학과 결과를 입력하고, 담임이 확인하고 모아 봅니다. 쓰던 학교는 학생 자료·학생 주소·접속코드·교사 PIN을 그대로 둔 채 파일 몇 개만 바꿉니다.

무엇이 생기나

  • 학생이 실제로 원서를 낸 곳과 결과를 입력합니다. 상담카드에 적은 대학이 미리 불러와지고, 학생은 대학마다 지원함 / 안 함을 고릅니다. 막판에 바꿔 낸 대학은 직접 추가합니다.
  • 결과는 1차 합격 · 1차 불합격 · 2차 미응시 · 예비 · 추가 합격 · 최종 합격 · 최종 불합격으로 나눠 적습니다. 1차 탈락, 1차 합격 후 면접 미응시, 면접 본 뒤 최종 탈락이 서로 구분됩니다.
  • 담임이 확인한 결과는 잠겨서 학생이 더 고칠 수 없습니다. 입력하지 않는 학생은 담임이 대신 입력합니다. 누가 언제 무엇을 바꿨는지는 시트에 한 줄씩 남습니다.
  • 예비 번호 · 다음 발표일 · 합격 차수(최초 합격, N차 추합, 전화 추합) · 비고를 적고, 추합 일정은 날짜순으로 모아 봅니다.
  • 담임 화면에서 학생별·대학별로 모아 보고 CSV로 내려받습니다. 학생 입력은 선생님이 켜고 끌 수 있습니다.
그대로 남는 것 · 학생 상담카드 주소 · 접속코드 · 학생이 쓴 상담카드 · 변경이력 · 교사 메모 · 교사 PIN. 결과는 상담카드와 따로 발표결과 시트에 저장되어 상담카드 내용은 바뀌지 않습니다.

원본 주소 (사본 만들기)

처음 쓰는 학교도, 이미 쓰는 학교도 이 주소에서 시작합니다.

주소를 열면 사본 만들기 단추가 나옵니다. 사본은 연 선생님의 Google 드라이브에 만들어지고, 학생 자료도 그 사본에만 저장됩니다. 원본 제작자나 다른 학교는 볼 수 없습니다.

B. 9월판(V9.8)을 쓰는 학교 — 약 10분

9월에 받은 판(서버 v1.8.0 또는 v1.7.0)을 쓰는 학교입니다. 바꿀 파일은 넷입니다.

Result새로 만들기 · 필수
Teacher내용 바꾸기 · 권장
Manual내용 바꾸기 · 권장

Index(학생 상담카드)와 Calendar는 그대로 둡니다. Teacher를 바꾸면 교사 대시보드에 🏁 발표 결과 단추가 생기고, Manual을 바꾸면 매뉴얼에 결과 화면 안내(6-4장)가 들어갑니다. 둘 다 그대로 두어도 결과 기능은 작동합니다.

  1. 백업 먼저

    쓰던 스프레드시트에서 파일 → 사본 만들기, 이름 끝에 _백업을 붙입니다. 이 사본은 열지도 고치지도 말고 그대로 두세요. 문제가 생기면 여기서 예전 코드를 가져와 되돌립니다(되돌리기).

  2. 복사해 올 곳 만들기

    위의 원본 주소로 사본을 하나 더 만들고, 그 사본에서 확장 프로그램 → Apps Script를 엽니다. 왼쪽 파일 목록에 코드 · Index · Teacher · Manual · Calendar · Result가 보입니다.

    이 사본은 파일을 복사해 오는 곳일 뿐입니다. 여기서 설치(setupSystem)를 하거나 명단을 넣거나 배포하지 마세요. 다 옮긴 뒤 지워도 됩니다.

  3. 코드 내용 바꾸기

    쓰던 스프레드시트에서 확장 프로그램 → Apps Script를 엽니다(탭이 두 개가 됩니다). 왼쪽의 원래 있던 코드.gs를 열고 Ctrl+A → Delete로 비웁니다. 복사해 올 곳의 코드를 열어 Ctrl+A → Ctrl+C, 쓰던 쪽에 Ctrl+V → Ctrl+S(저장).

    .gs 파일을 새로 추가하지 마세요. 원래 있던 파일의 내용을 바꿉니다. 파일 이름이 Code.gs여도 같습니다.

  4. Result 새로 만들기

    쓰던 쪽에서 파일 옆 ＋ → HTML, 이름을 Result(대문자 R, .html은 저절로 붙음)로 만듭니다. 안에 미리 들어 있는 기본 내용을 Ctrl+A → Delete로 지우고, 복사해 올 곳의 Result 내용을 붙여넣고 저장합니다.

  5. Teacher · Manual 내용 바꾸기 (권장)

    3번과 같은 방법으로 Teacher와 Manual의 내용을 바꾸고 저장합니다. Teacher는 파일이 커서 붙여넣고 저장하는 데 몇 초 걸립니다.

  6. 새 버전으로 배포

    배포 → 배포 관리 → 연필(✏) → 버전: 새 버전 → 배포. ‘새 배포’가 아닙니다. 배포 관리에서 고쳐야 학생에게 준 주소가 그대로입니다.

    권한 승인 창은 뜨지 않습니다(새로 필요한 권한이 없습니다). setupSystem도 다시 하지 않아도 됩니다.

  7. 확인하고 학생에게 결과 주소 안내

    끝난 뒤 확인의 세 가지를 보고, 학생 안내문(학생용 사용 안내 페이지 링크 포함)과 함께 학생용 결과 주소를 보냅니다.

  1. Index도 바꾸기

    B의 3~5번을 할 때 Index도 같은 방법으로 내용을 바꿉니다. 학생 상담카드 화면 파일이라 크기가 약 4MB입니다. 복사·붙여넣기·저장에 수십 초 걸릴 수 있으니 저장이 끝날 때까지 기다리세요. 예전 판은 Index와 Teacher가 한 세트라, 둘 중 하나만 바꾸면 교사 화면에서 전문대 지원 내용이 빠집니다.

    전형일정 달력만 따로 링크로 주고 싶을 때만 ＋ → HTML, 이름 Calendar로 만들어 붙여넣습니다. 달력은 상담카드 안에 이미 들어 있어서 없어도 됩니다. 이미 있던 학교는 내용을 바꿉니다.

    B의 6번(새 버전 배포)까지 한 뒤, 스프레드시트를 새로고침하고 수시 상담카드 → 고급 · 문제가 생겼을 때 → 시스템 시트 다시 만들기 (setupSystem)를 한 번 누릅니다. 예전 판에서 쓰던 시트 머리글을 지금 규격으로 맞춥니다. 학생 자료는 지워지지 않고, 완료 창은 뜨지 않습니다. 끝났는지는 ✅ 지금 상태 점검하기로 봅니다.

D. 11월에 이미 신버전을 받은 학교 — 약 5분

11월 12~13일에 신버전을 받아 간 학교입니다. 교사 대시보드 제목 아래 서버 v…를 봅니다.

  • 서버 v1.9.0 — 꼭 바꿔 주세요. 여러 명이 동시에 저장하면 다른 학생의 결과가 지워질 수 있던 판입니다. 코드와 Result 두 파일의 내용을 바꿉니다. Result는 새로 만들지 말고, 이미 있는 Result의 내용을 바꿉니다.
  • 서버 v1.9.1 · v1.9.2 — 코드와 Result 두 파일의 내용을 바꿉니다(Result는 새로 만들지 말고 이미 있는 것의 내용만). 고친 것은 다음과 같습니다. ① 스프레드시트와 Apps Script의 시간대가 서로 다르게 설정된 학교에서 ‘다음 발표일’이 하루 앞당겨 보일 수 있던 것(v1.9.1만 해당). ② 학교가 직접 만든 ‘발표결과’라는 이름의 시트가 이미 있을 때 그 시트에 덧붙여 쓰던 것(v1.9.1만 해당 — 이제는 손대지 않고 이름을 바꾸라고 안내합니다). ③ 그런 시트가 있는 학교에서 학년말에 메뉴 ‘학생 작성 자료 전체 초기화’를 누르면 그 시트 내용까지 비우던 것(v1.9.1·v1.9.2). ④ 결과 화면에서 로그아웃한 뒤에도 맨 위에 앞사람 이름이 남던 것(교실 공용 PC에서 다음 학생에게 보임 — Result). 대부분의 학교는 ①~③에 해당하지 않지만, 바꿔 두면 안전합니다.

순서는 B의 0~3번(필요하면 4번)과 6번입니다. 이미 입력된 결과와 상담카드는 그대로 둔 채 바뀝니다.

A. 처음 쓰는 학교 — 약 30분

상담카드와 발표 결과가 함께 들어 있는 판 하나만 설치하면 됩니다. 예전 판을 먼저 깔 필요가 없습니다.

  1. 사본 만들기

    원본 주소 → 사본 만들기. 이 사본이 우리 학교 것입니다. 이름은 알아보기 쉽게 바꿔도 됩니다.

  2. 설치(setupSystem) 한 번 + 권한 승인

    사본에서 확장 프로그램 → Apps Script → 위쪽 함수 목록에서 setupSystem → 실행. 권한 창이 뜨면 권한 검토 → 계정 선택 → 고급 → (안전하지 않은 페이지로) 이동 → 허용. 직접 만든 사본이라 뜨는 확인 절차입니다. 완료 창은 뜨지 않습니다. 스프레드시트를 새로고침하면 위쪽에 수시 상담카드 메뉴가 생깁니다.

  3. 학생 명단 → ① 학생명단 정리 + 접속코드 만들기

    학생명단 시트에 반·번호·이름을 넣고 메뉴 ①을 누릅니다. 접속코드가 학생마다 만들어집니다.

  4. ② 교사 PIN 바꾸기

    처음 PIN은 모두 같으므로 바로 바꿉니다. 이 PIN으로 교사 대시보드와 교사용 결과 화면에 들어갑니다.

  5. ③ 웹앱 배포 → 🔗 배포 주소 등록

    Apps Script에서 배포 → 새 배포 → ⚙ 웹 앱, 다음 사용자로 실행: 나, 액세스 권한: 모든 사용자 → 배포 → /exec로 끝나는 주소를 복사합니다. 스프레드시트로 돌아와 🔗 배포 주소 등록 (배포 직후 1회)에 붙여넣습니다.

    처음 배포할 때만 ‘새 배포’입니다. 그 뒤에 파일을 고치면 B의 6번처럼 배포 관리에서 새 버전으로 바꿉니다.

  6. ④ 학생 접속코드 안내표 → 학생에게 전달

    학생접속코드_안내 시트가 만들어집니다. 접속코드는 개인정보라 반별로 나눠 개별로 전달합니다.

  7. 발표 결과 주소 안내

    수시 발표가 시작될 즈음 🔗 학생용·교사용 주소 보기 아래쪽 수시 발표 결과의 학생용 주소를 학생 안내문과 함께 보냅니다.

각 단계의 화면 설명은 사본 안 매뉴얼(배포 뒤 …/exec?page=manual) 1~5장에 있습니다. 막히면 ✅ 지금 상태 점검하기가 남은 단계를 알려 줍니다.

끝난 뒤 확인 (B·C·D)

  1. 상태 점검

    스프레드시트 새로고침(F5) → 수시 상담카드 → ✅ 지금 상태 점검하기. 5번이 “네 화면 모두 정상입니다.”, 7번에 수시 발표 결과 줄이 보이면 됩니다.

  2. 판 확인

    교사 대시보드를 Ctrl+Shift+R로 새로고침 → 제목 아래가 서버 v1.9.3인지 봅니다. 결과 화면 맨 아래에는 화면 발표결과 1.0.2이 찍힙니다.

  3. 결과 주소

    🔗 학생용·교사용 주소 보기 아래쪽 수시 발표 결과에 주소 두 줄이 나옵니다. 학생용은 …/exec?page=result&who=student, 교사용은 …/exec?page=result&who=teacher로 끝납니다. 교사용을 열어 교사 PIN으로 들어가 학생 목록이 보이면 끝입니다.

학생 안내문

학생에게는 우리 학교 결과 입력 주소와 학생용 사용 안내 페이지 두 가지를 보냅니다. 학생용 안내 페이지는 실제 결과 화면 그림(가상 학생)으로 들어가기 · 원서 낸 곳 고르기 · 결과 고르기 · 저장 · 🔒 잠긴 줄 · 자주 묻는 것을 설명합니다. 모든 학교가 같은 페이지를 써도 됩니다.

열어 보기

단톡방·클래스룸에 붙여넣을 글입니다. 입력 주소 자리에 학생용 결과 주소(메뉴 🔗 학생용·교사용 주소 보기 아래쪽 ‘수시 발표 결과’의 학생용, …/exec?page=result&who=student)를 넣으세요.

이것만은 하지 마세요

  • ‘새 배포’ — 새 주소가 생겨 학생에게 준 주소가 안 맞게 됩니다. 늘 배포 관리 → 연필 → 새 버전.
  • .gs 파일 새로 추가 — 코드가 두 벌이 되어 ‘already been declared’ 오류가 납니다. 원래 있던 코드.gs의 내용만 바꿉니다.
  • 메뉴 ‘학생 작성 자료 전체 초기화’ — 되돌릴 수 없습니다. 업데이트와 상관없는 메뉴입니다.
  • 시트 탭 지우기·이름 바꾸기, 시트 1행 머리글 고치기 — 앱이 시트 이름과 머리글 이름으로 칸을 찾습니다.
  • 복사해 올 곳(사본)에 명단을 넣거나 그 주소를 학생에게 주기 — 그 사본은 빈 시트입니다.

되돌리기

업데이트 뒤 문제가 생기면 0번 백업 사본의 확장 프로그램 → Apps Script에서 예전 코드.gs(바꿨다면 Teacher·Manual도) 내용을 복사해 쓰던 쪽에 다시 붙여넣고, 배포 관리 → 새 버전으로 배포합니다. 상담카드는 예전처럼 돌아가고, 학생 자료와 그사이 입력된 발표 결과 시트는 그대로 남습니다. 다시 신버전으로 오면 결과를 이어서 씁니다.

백업 사본의 시트를 쓰던 시트로 옮겨 붙이지는 마세요. 업데이트 뒤에 학생이 쓴 내용이 사라집니다. 되돌리는 것은 코드 파일뿐입니다.

자주 묻는 질문

자료·업데이트
업데이트하면 학생이 쓴 상담카드가 지워지지 않나요?
지워지지 않습니다. 업데이트는 Apps Script의 코드·화면 파일만 바꾸고, 학생 자료는 스프레드시트에 따로 있습니다. 9월까지 나온 판 세 가지로 자료를 쌓은 시트에 덮어쓰고 시트 전체를 칸 단위로 비교했는데, 새로 생긴 결과 시트 두 개와 설정 시트 한 줄 말고는 바뀐 칸이 없었습니다(확인한 방법). 그래도 0번 백업은 꼭 해 두세요.
학생에게 주소나 접속코드를 다시 알려 줘야 하나요?
상담카드 주소와 접속코드는 그대로입니다. 결과 화면 주소 하나만 새로 알려 주면 됩니다. 학생은 상담카드와 같은 반·번호·이름·접속코드로 들어갑니다. 같은 기기에서 상담카드에 로그인해 두었다면 바로 열립니다.
권한 승인 창이 또 뜨나요?
뜨지 않습니다. 새 코드는 예전 판과 같은 권한만 씁니다. 혹시 뜨면 처음 설치할 때처럼 고급 → 이동 → 허용을 누르면 됩니다.
setupSystem을 다시 해야 하나요?
B·D는 하지 않아도 됩니다. 결과 시트는 결과 화면을 처음 열 때 저절로 생깁니다. C는 한 번 합니다. 실수로 눌러도 학생 자료와 결과는 지워지지 않고, 선생님이 꺼 둔 ‘학생 입력’ 설정도 그대로입니다.
Teacher·Manual·Index도 꼭 바꿔야 하나요?
B는 코드와 Result만 있으면 결과 기능이 작동합니다. Teacher를 바꾸면 교사 대시보드에 🏁 단추가 생기고, Manual을 바꾸면 매뉴얼에 결과 안내가 들어가므로 같이 바꾸기를 권합니다. Index는 B에서는 그대로 둡니다. C(V9.7 이하)는 Index·Teacher·Manual을 모두 바꿉니다.
시트에 제가 따로 만든 탭과 칸이 있는데 괜찮나요?
괜찮습니다. 새 코드는 원래 앱이 쓰던 칸과 새로 만드는 결과 시트 두 개(발표결과·발표결과_이력)에만 씁니다. 선생님이 덧붙인 시트 탭과 명단 오른쪽에 덧붙인 칸은 그대로입니다(시험으로 확인). 다만 선생님이 만든 탭 이름이 마침 발표결과라면, 결과 화면이 그 탭에 손대지 않고 멈춰 이름을 바꾸라고 안내합니다(이럴 때는). 학년말에 ‘학생 작성 자료 전체 초기화’를 눌러도 그 탭은 비우지 않습니다.
새 사본을 만들어 거기로 옮겨 가면 안 되나요?
권하지 않습니다. 새 사본은 웹앱 주소가 새로 생기고 학생 자료가 비어 있어, 자료를 옮기고 학생 전원에게 주소를 다시 안내해야 합니다. 쓰던 시트에서 파일 내용만 바꾸는 쪽이 빠르고 안전합니다.
업데이트하다가 학생이 접속해 있으면 어떻게 되나요?
학생 화면은 배포 관리에서 새 버전을 누르는 순간 바뀝니다. 그 전까지는 예전 판이 그대로 돌아갑니다. 작성 중이던 학생은 새로고침하면 됩니다. 수업 시간을 피해 하면 더 좋습니다.
결과 입력
학생이 거짓으로 입력하면요?
학생이 입력한 줄은 담임 화면에 확인 전(점선)으로 보입니다. 담임이 확인하면 잠겨 학생이 더 고칠 수 없습니다. 누가 언제 무엇을 바꿨는지는 발표결과_이력 시트에 남습니다. 담임 화면의 확인분만 집계를 켜면 확인한 결과만 숫자에 넣습니다.
학생 입력을 막고 담임만 입력할 수 있나요?
교사용 결과 화면 위쪽 학생 입력 단추로 끕니다. 꺼 두면 학생은 자기 결과를 보기만 하고, 담임은 그대로 입력합니다. 언제든 다시 켤 수 있습니다.
결과를 안 넣는 학생은요?
교사용 결과 화면 학생별 탭에서 그 학생의 입력·수정을 눌러 담임이 대신 넣습니다. 상담카드를 쓰지 않은 학생도 됩니다. 담임이 넣은 줄은 바로 확인 상태가 됩니다. 위쪽 거르기에서 결과 미입력 학생만 골라 볼 수 있습니다.
상담카드에 적은 곳과 실제로 낸 곳이 달라요.
상담카드의 대학은 출발점일 뿐입니다. 내지 않은 곳은 안 함, 막판에 바꿔 낸 곳은 맨 아래 ＋ 4년제 추가 / ＋ 전문대 추가로 넣습니다. 결과를 넣은 뒤 학생이 상담카드를 고치면, 아직 손대지 않은 대학은 카드를 따라 바뀌고 이미 결과를 적은 줄은 그대로 남습니다.
1차 합격 후 면접에 안 간 경우는요?
2차 미응시를 고릅니다. 1단계에서 떨어지면 1차 불합격, 면접을 보고 떨어지면 최종 불합격입니다. 단계 없이 한 번에 뽑는 전형은 바로 최종 합격·최종 불합격을 고릅니다. 예비였다가 끝내 추합되지 않으면 최종 불합격으로 바꿉니다.
추합은 어떻게 관리하나요?
예비 번호와 다음 발표일을 적어 두면 교사용 화면 추합·발표 일정 탭에 날짜순으로 모입니다. 추합이 되면 추가 합격으로 바꾸고 합격 차수(1차 추합, 전화 추합 등)를 고릅니다. 예비 번호와 다음 발표일은 학생도 적을 수 있습니다.
여러 학생이 한꺼번에 저장하면 꼬이지 않나요?
저장은 한 명씩 차례로 처리됩니다. 학생 300명 시트에서 20명이 동시에 저장하는 시험을 세 번 했고, 60명 모두 저장되었으며 사라지거나 겹친 줄은 없었습니다. 붐비면 저장 단추에 ‘저장 차례를 기다리는 중…’이 뜨고 저절로 다시 보냅니다. 가장 늦은 학생은 1분 남짓 걸렸습니다. 담임과 학생이 같은 학생을 동시에 고쳐도 서로 덮어쓰지 않고, 나중에 저장한 쪽 화면이 최신 내용을 불러와 합쳐 줍니다.
정시 결과도 넣을 수 있나요?
이 화면은 수시용입니다(4년제 수시, 전문대 수시 1·2차).
엑셀로 받을 수 있나요?
교사용 결과 화면의 결과 CSV(학생별 한 줄씩)와 대학별 CSV로 내려받아 엑셀에서 엽니다. 지금 걸러 놓은 반·학생 기준입니다. 합격 결과는 개인정보이므로 학교 업무용 저장소에만 두세요.
담임 여러 명이 같이 쓰나요?
학교 하나에 사본 하나를 두고, 모든 담임이 같은 교사 PIN으로 들어갑니다. 반 거르기로 자기 반만 볼 수 있습니다. 결과 화면 위쪽 교사 이름 칸에 이름을 적어 두면 누가 고쳤는지 이력에 남습니다.

증상원인과 조치
결과 주소를 열었는데 학생 상담카드가 뜬다새 코드가 배포되지 않았습니다. 코드 내용을 바꿨는지 확인하고 배포 관리 → 연필 → 새 버전을 다시 하세요.
“화면 파일을 찾지 못했습니다”HTML 파일 이름이 정확히 Result가 아닙니다. 파일 오른쪽 ⋮ → 이름 바꾸기로 고친 뒤 새 버전으로 배포하세요.
‘already been declared’(이미 선언됨) 오류.gs 파일이 두 개가 되었습니다. 새로 만든 .gs 파일을 지우고, 원래 코드.gs의 내용을 바꾸세요.
화면이 예전 그대로다Ctrl+Shift+R로 새로고침하세요. 그래도 같으면 새 버전 배포를 빠뜨린 것입니다.
화면 맨 위에 붉은 띠 “○○ 화면 파일이 예전 버전입니다”띠에 적힌 파일만 원본 사본에서 다시 붙여넣고 새 버전으로 배포하세요(주로 C의 학교).
상태 점검 5번에 “Result”가 빠졌다고 나온다Result 파일을 아직 만들지 않았습니다. B의 4번을 하세요.
교사 대시보드에 🏁 발표 결과 단추가 없다Teacher를 바꾸지 않았거나, 배포 주소가 등록되지 않았습니다. 🔗 배포 주소 등록에 /exec 주소를 넣으면 생깁니다. 단추 없이 교사용 결과 주소로 바로 들어가도 됩니다.
대학별 집계가 대학이 아니라 ‘수시’·‘수시1차’로 묶인다예전 판 시트 머리글입니다. 교사 대시보드를 한 번 열면 저절로 고쳐지고, 바로 고치려면 고급 → 지원행 시트 다시 만들기.
학생이 “담임 선생님만 입력합니다”라는 안내를 본다학생 입력이 꺼져 있습니다. 교사용 결과 화면 위쪽 학생 입력을 켜세요.
저장했더니 “먼저 바꾼 내용을 불러와 … 합쳤습니다”정상입니다. 그사이 담임(또는 다른 창)이 저장해서, 최신 내용 위에 입력하던 내용을 다시 얹어 둔 것입니다. 화면을 확인하고 저장을 한 번 더 누르세요.
“현재 파일을 열 수 없습니다”브라우저에 Google 계정이 여러 개 로그인되어 있을 때 나는 오류입니다. 시크릿 창에서 열어 보세요. 시크릿 창에서 열리면 설치·배포는 정상입니다(매뉴얼 9장).
결과 화면에 “이미 ‘발표결과’ 시트가 있는데, 발표 결과 화면이 만든 시트가 아닙니다”선생님이 예전부터 직접 만들어 쓰던 같은 이름의 시트가 있는 경우입니다. 결과 화면은 그 시트에 아무것도 쓰지 않고 멈춘 상태입니다. 시트 탭을 오른쪽 클릭 → 이름 바꾸기로 발표결과_학교처럼 바꾸고 결과 화면을 다시 여세요. 내용은 그대로 남고, 결과 화면은 새 ‘발표결과’ 시트를 만들어 씁니다.
원본 주소를 열었는데 사본 만들기가 안 된다학교 Google Workspace 계정이 바깥 파일을 막아 둔 경우가 있습니다. 개인 Gmail 계정으로 열어 보세요.

그 밖의 문제는 ✅ 지금 상태 점검하기 화면과 교사 대시보드 맨 위(제목과 그 아래 줄)를 캡처해서 물어보시면 바로 원인을 찾을 수 있습니다.

이렇게 확인했습니다

쓰던 학교가 덮어썼을 때 자료가 상하지 않는지를 가장 먼저 봤습니다. 모두 가상 학생으로 시험했습니다.
